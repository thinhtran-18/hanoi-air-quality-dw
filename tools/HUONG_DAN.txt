THƯ MỤC .work — CÔNG CỤ HỖ TRỢ ĐỀ TÀI KHÔNG KHÍ HÀ NỘI

Các file để nộp và import nằm ở thư mục cha. .work giữ mã nguồn và dữ liệu
quan trắc gốc để kiểm chứng, tái tạo dữ liệu và tài liệu; không phải kho dữ liệu
Star Schema hoàn chỉnh. Không nên xóa cả .work.

FILE CẦN GIỮ
csv_goc/              325 file CSV nén .gz từ OpenAQ; giữ nguyên tên gốc để khớp manifest.
tai_nguon_va_sql.py   Tải dữ liệu hai trạm năm 2024, tạo T-SQL và manifest.
tao_sql_server.py    Tạo lại SQL Server từ CSV hiện tại, không tải mạng.
kiem_tra_csv.py       Thống kê dữ liệu gốc, kiểm tra NULL/giá trị âm, ghép CSV.
tao_tai_lieu.py       Tạo hai Word đề xuất đề tài và phân công 5 người.
dinh_dang_word.py     Hàm dùng chung: font, đoạn văn, bảng, khổ giấy cho Word.
chuan_hoa_word.py     Thay các cụm từ cũ trong hai Word bằng nội dung nguồn OpenAQ.
xuat_pdf_word.ps1     Xuất Word sang PDF và văn bản từng trang để kiểm tra trình bày.

MỐI LIÊN HỆ
OpenAQ -> tai_nguon_va_sql.py -> csv_goc/ + SQL + manifest tại thư mục cha.
csv_goc/ -> kiem_tra_csv.py -> CSV ghép tại thư mục cha.
Manifest ghi đường dẫn tải của 325 file gốc; tên file gốc được giữ nguyên.
CSV và SQL chứa cùng bộ phép đo nhưng thứ tự dòng có thể khác nhau.
tao_tai_lieu.py dùng dinh_dang_word.py để tạo Word; chuan_hoa_word.py chuẩn hóa
nội dung, xuat_pdf_word.ps1 tạo bản kiểm tra trong pdf_kiem_tra/ (có thể xóa).

Chỉ chạy bước cần dùng. Python tạo/sửa Word cần gói python-docx;
xuất PDF cần Microsoft Word trên Windows. Tạo lại sẽ ghi đè file đầu ra;
không chạy tạo Word nếu đã chỉnh tay tài liệu mà chưa lưu bản sao.
SQL tạo hanoi_air_vn nếu chưa có; không DROP DATABASE. Chạy lại không thêm
trùng khóa; báo lỗi nếu bản ghi đã có khác nguồn. Bộ công cụ này chuẩn bị
nguồn, chưa triển khai ETL kho.

SQL SERVER VÀ VISUAL STUDIO
1. Dùng SQL Server Database Engine (đã thử trên SQL Server 2025 cục bộ).
2. Mở hanoi_air_quality_vn_monitoring_real.sql trong SSMS hoặc SQL editor của
   Visual Studio có kết nối SQL Server, rồi Execute toàn bộ script.
   Tài khoản cần quyền tạo database nếu hanoi_air_vn chưa tồn tại.
   Không dùng script nạp dữ liệu này làm file Build của SQL Database Project;
   nếu dùng SSDT, chạy riêng hoặc tổ chức lại thành post-deployment script.
3. Kết quả mới: database hanoi_air_vn, bảng dbo.air_quality_hourly, 23.036 dòng.
   Trạm 2161299: 13.015 dòng; trạm 2161301: 10.021 dòng.
4. SQL chứa GO để chia batch. Khi gọi từ mã C#/ADO.NET, không gửi nguyên file
   có GO vào một SqlCommand; dùng công cụ thực thi script hoặc tách batch.
5. CSV là UTF-8 có BOM, dấu phẩy, có tiêu đề; không cần sửa dữ liệu.
   Với SSIS Flat File Connection Manager: chọn code page 65001, dấu phẩy,
   text qualifier dấu ngoặc kép, header ở dòng đầu; nên đọc cột thành text
   Unicode ở staging rồi chuyển kiểu khi nạp.
6. Ánh xạ CSV -> SQL:
   location_id -> location_id (INT)
   sensors_id -> sensor_id (INT)
   location -> location_name (NVARCHAR(160))
   datetime -> observed_at (DATETIMEOFFSET(0), giữ +07:00)
   lat -> latitude (DECIMAL(10,6)); lon -> longitude (DECIMAL(10,6))
   parameter -> parameter (NVARCHAR(20)); units -> unit (NVARCHAR(40))
   value -> value (FLOAT(53)); id là IDENTITY, không có cột tương ứng trong CSV.
   Một dòng là một phép đo theo trạm/cảm biến/thời điểm/chất ô nhiễm.
7. Manifest là đường dẫn tương đối trong kho OpenAQ, không phải lệnh SQL.
   Ghép tiền tố https://openaq-data-archive.s3.amazonaws.com/ để có URL tải.
8. Tạo lại T-SQL từ CSV hiện tại: python .work/tao_sql_server.py
   SQL đã chứa dữ liệu, do đó không cần import thêm CSV nếu đã chạy SQL.
   Công cụ tạo Word có thể ghi đè chỉnh sửa thủ công: không cần chạy lại
   vì hai Word hiện tại đã được nhóm cập nhật sang SQL Server.
